# PS-09 optimised BGE encoder

Submission file: **`team.py`** (defines `setup()` and `encode(texts)`; the defaults at the top of the file are the
submitted configuration, so no environment variables are needed). Status and evidence: [TRACKER.md](TRACKER.md).
Report: [docs/technical_report.md](docs/technical_report.md) → `reports/PS09_Final_Report.pdf`.

| File | Purpose |
|---|---|
| `team.py` | The optimised encoder. `PS09_STAGE=0..5` presets switch each optimisation on, for the ablation. |
| `validate.py` | Accuracy gate: worst-case cosine against the official passage and query references (gate 0.9995). |
| `profile_run.py` | Profiler evidence: Chrome trace, top kernels, GPU time by category, idle-gap timeline. |
| `run_ablation.py` | Runs the official `bench.py` per stage; appends to `<out-dir>/ablation.csv` and `ABLATION.md` (with flags, peak GPU memory). |
| `demo.py` | Judge demo: reference vs ours on the same texts, cosine, padding, throughput, latency, search. |
| `run_all.sh` | **GPU workflow (Ubuntu)**: everything, restartable, results in `results_gpu/`. |
| `run_all.ps1` | **Windows workflow (no GPU)**: environment, CPU correctness tests, workload and precision analysis, report. |
| `install_ps09.sh` | Self-extracting copy of the code (GENERATED by `scripts/build_installer.py`; never edit by hand). |
| `tests/` | `test_correctness.py` (edge cases vs `reference.py`, CPU and GPU), `test_lowprec_cpu.py` (FP16 paths on CPU). |
| `scripts/` | `precision_study.py`, `workload_stats.py`, `live_latency.py`, `full_check.py`, `apply_best_config.py`, `collect_results.py`, `make_report.py`, `env_report.py`, `build_installer.py`. |
| `docs/` | Planning documents (PDF), technical report source, demo guide, judge Q&A. |
| `results_cpu/`, `results_cpu_dryrun/` | CPU evidence (this laptop; teammate's cloud CPU). `results_gpu/` holds GPU evidence. |

## Windows laptop (no NVIDIA GPU): development and CPU checks

```powershell
winget install --id Python.Python.3.12 --scope user      # once, if Python is missing
powershell -ExecutionPolicy Bypass -File .\run_all.ps1              # env, dataset, tests, accuracy, workload stats
powershell -ExecutionPolicy Bypass -File .\run_all.ps1 -Precision   # + FP16 precision study (CPU emulation, ~30 min)
powershell -ExecutionPolicy Bypass -File .\run_all.ps1 -Report      # rebuild the report (after copying results_gpu/ back)
```

## Ubuntu RTX machine: GPU measurements

Get the code there with `git pull` (preferred) or by copying `install_ps09.sh` over AnyDesk and running
`bash install_ps09.sh ~/ps09 --no-run`. Then, in the project folder:

```bash
bash run_all.sh            # env + baseline, edge-case tests, accuracy, ablation (20k), budget sweep, latency, profiles
bash run_all.sh --full     # also the final 100k official bench and the 100k accuracy check (~30-40 min more)
bash run_all.sh --step sweep   # one step only: env test validate ablation sweep latency profile full collect
python scripts/apply_best_config.py --sweep results_gpu/token_budget/ablation.csv --stage 4 --apply   # set defaults
```

Every step is skipped if its result already exists (delete the file to redo it); every step's OK/FAIL is logged in
`results_gpu/STATUS.txt`; `results_gpu/SUMMARY.md` is generated from the result files. Copy `results_gpu/` back to
the Windows laptop (it is small; `.npy` files are git-ignored) and run `run_all.ps1 -Report`.

**Baseline note.** The 1-hour FP32 reference over 100k passages is never re-run. `reference.py` pads every input to
512 tokens, so its time per passage does not depend on the text, and `bench.py`'s speed-up is computed from a
reference-throughput JSON: the 5,000-passage sample (`results_gpu/hardware/ref_throughput.json`) is used.

## Switches (environment variables, for experiments only)

`PS09_STAGE`, `PS09_FP16`, `PS09_SORT`, `PS09_BUDGET`, `PS09_BUCKET`, `PS09_OVERLAP`, `PS09_CLS_ONLY`, `PS09_COMPILE`,
`PS09_GRAPH`, `PS09_TOKEN_BUDGET`, `PS09_MIN_FILL`, `PS09_CHUNK`, `PS09_RES32`, `PS09_BF16`, `PS09_FP16_ACCUM`,
`PS09_STRICT_REDUCTION`, `PS09_MODEL` (a local model folder works too), `PS09_DEBUG`.
To change the submitted configuration, edit `DEFAULT_STAGE`, `DEFAULT_TOKEN_BUDGET`, `DEFAULT_RES32` at the top of
`team.py` (or use `apply_best_config.py --apply`), then run `python scripts/build_installer.py`.
